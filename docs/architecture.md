# Architecture

`/api/agent` 接收事件、消息和会话状态。消息事件先调用 Planner，模型只能从受支持动作中选择；服务端通过 `normalizePlan` 修正动作、抽牌数量、主题和牌位，并限制连续澄清。抽牌完成事件会调用 `/api/rag-retrieve`，将返回证据交给 Reading Prompt。

会话状态包含问题摘要、主题、已抽牌、解读次数和澄清标记。前端保存状态并根据动作显示对话卡片或透明牌阵。

检索分两层：

1. 精确层根据已抽牌 ID、正逆位和问题主题返回牌面象征、对应场景牌义与智慧指引。
2. 语义层可用 Jina 查询向量补充最相关片段，但候选集合仍受已抽牌和正逆位约束。语义服务不可用时，接口返回完整精确结果。

公开仓库中的知识内容仅用于展示数据结构。生产语料与 embedding 索引未纳入版本控制。
